## 1. 接入与通用约定

### 1.1 基础信息

- Base URL：`http://{服务器IP}:10100/api/open/v1`
- 本机：`http://localhost:10100/api/open/v1`
- 令牌：`simulator/conf/gateway.json` 的 `openTokens`
- 请求头：`X-Open-Token: <公开令牌>`
- 可选：`X-Agent-Id: <agentId>`（≤64 字符，仅用于同队多实例区分与日志）
- 重试标识：`X-Retry-Of: <原始 requestId>`（超时重传/故障重试，不计冗余调用）

读取令牌（**勿打印到日志、勿提交**）：

```bash
TOKEN=$(python3 -c "import json;print(json.load(open('simulator/conf/gateway.json'))['openTokens'][0])")
```

### 1.2 响应包络

```json
{"code":0,"msg":"ok","data":{},"time":"10:03:02.125480","tsUs":1800237782125480}
```

- `code`：0 成功；非 0 见错误码；
- `time`/`tsUs`：服务器本地时间与 Unix 微秒，同源；
- 提交类请求带 `requestId`（≤64 字符）实现幂等；
- 建议调用超时 6 秒；触发频控（1005）应退避重试。

### 1.3 错误码

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 1001 | 参数非法 |
| 1002 | 令牌缺失或无效 |
| 1003 | 资源不存在 |
| 1004 | 状态冲突（含链路断开/不连通/QoS 不满足） |
| 1005 | 触发频控 |
| 1006 | 令牌权限不足 |
| 2000 | 服务器内部错误 |

## 2. 数据模型

### 2.1 节点

- `nodeType`：`uav`（无人平台）、`ground`（地面节点）、`air`（空中节点）；
- `status`：`online` / `offline`；
- 业务节点：`uav` + `air`；地面节点通常只做转发，不在 `sim-nodes.json` 的业务注入表中；
- 典型 IP：UAV `10.1.1.x`，AIR `10.3.0.x`，GND `10.2.x.x`。

### 2.2 链路

- `linkType`：`fiber`、`satcom`、`vhf`、`uhf`、`microwave`、`5g`；
- `status`：`up` / `down`；
- `params`：
  - `delayMs`（毫秒，float）
  - `jitterMs`（毫秒，float）
  - `bandwidthBps`（bit/s，int）
  - `ber`（误码率，小数）
  - `packetLossRate`（丢包率，0~1 小数）
- 参数范围由 `simulator/conf/linkTypes.json` 约束。

### 2.3 业务

- `serviceType`：`data`、`image`、`voice`、`video`；
- `status`：`pending`、`running`、`stopped`、`finished`、`failed`；
- `priority`：优先级；
- `requirement`：QoS 需求上限/带宽下限；
- `path`：`pathId` + `segments`；
- `actual`：最近约 1 秒实测值：
  - `avgDelayMs`
  - `jitterMs`
  - `effBwBps`
  - `errPct`（百分比 0~100）
  - `packetLossRate`（0~1）
  - `qosMeet`（true/false，实测是否达标）

## 3. 接口清单与示例

| # | 方法 | URL | 用途 |
| --- | --- | --- | --- |
| 1 | GET | `/topology` | 网络拓扑 |
| 2 | GET | `/nodes` | 节点列表 |
| 3 | GET | `/nodes/{nodeId}` | 节点详情/状态 |
| 4 | GET | `/links` | 链路列表（含参数） |
| 5 | GET | `/links/{linkId}` | 链路状态 |
| 6 | GET | `/services` | 业务列表 |
| 7 | GET | `/services/{serviceId}` | 业务详情/实测 |
| 8 | POST | `/services/{serviceId}/path` | 设置业务路径 |
| 9 | GET | `/services/{serviceId}/path` | 查询业务路径 |
| 10 | GET | `/events` | 事件轮询 |
| 11 | GET | `/time` | 服务器时间 |
| 12 | POST | `/simulation/start` | 启动仿真 |

> **已知限制**：`POST /simulation/start` 在当前镜像**未实现**（返回 1003「未知接口」）。
> 起测试要走 UI 的 `POST /sdn-ui/start`（nginx 服务端注入 ctrl 令牌，非公开 token）。

### 3.1 拓扑/链路/业务

```bash
curl -sS -H "X-Open-Token: $TOKEN" \
  http://localhost:10100/api/open/v1/topology

curl -sS -H "X-Open-Token: $TOKEN" \
  "http://localhost:10100/api/open/v1/links?status=up"

curl -sS -H "X-Open-Token: $TOKEN" \
  "http://localhost:10100/api/open/v1/services?status=running&size=500"
```

分页参数：`page`、`size`，默认单页 500。

> **构图要点**：`/topology` 的 links **不带 params**，链路 QoS 参数必须从 `/links` 取。
> 详见 [拓扑构建与容量记账](../algorithms/拓扑构建与容量记账.md)。

### 3.2 业务详情

```bash
curl -sS -H "X-Open-Token: $TOKEN" \
  http://localhost:10100/api/open/v1/services/SVC0007
```

重点看 `requirement`、`path.segments`、`actual`、`actual.qosMeet`。

### 3.3 事件轮询

```bash
curl -sS -H "X-Open-Token: $TOKEN" \
  "http://localhost:10100/api/open/v1/events?sinceTsUs=0&limit=100"
```

建议轮询间隔 ≤10 秒；用 `nextSinceTsUs` 作为下一次游标。
事件类型与注入机制见 [感知口径与事件机制](../perception/感知口径与事件机制.md)。

### 3.4 设置路径

```bash
curl -X POST -H "X-Open-Token: $TOKEN" -H "Content-Type: application/json" \
  http://localhost:10100/api/open/v1/services/SVC0007/path \
  -d '{
    "requestId":"agt01-20261113150500-001",
    "srcNodeId":"UAV0012",
    "dstNodeId":"UAV0088",
    "segments":[
      {"type":"link","id":"L00201"},
      {"type":"link","id":"L00112"}
    ]
  }'
```

响应：`accepted`/`rejected`、`pathId`、`effectiveTime`、`effectiveTsUs`；rejected 附 `reason`。

### 3.5 启动仿真（通常由页面调用）

```bash
curl -X POST -H "X-Open-Token: $TOKEN" -H "Content-Type: application/json" \
  http://localhost:10100/api/open/v1/simulation/start \
  -d '{"requestId":"c-20261113-001","suiteId":"sce20261031-conf02","scenarioId":"sce01","scriptId":"script-01"}'
```

`requestId` 幂等；同 requestId 重复调用不重复启动。

## 4. 路径下发与校验

### 4.1 segments

- `type=link`：邻接段，严格逐跳，路径必须使用该链路；并行链路由此区分；
- `type=node`：必经节点约束；节点段前后由系统按最小时延自动补齐链路，补齐链路计入路径与计分；
- 纯链路段序列是标准用法，评测计分以此口径为准。

### 4.2 受理规则

- `accepted`：受理并执行；
- `rejected`：
  - 1001：段不存在/段类型非法/段列表不连续；
  - 1004：链路断开或不连通/参数不满足业务 QoS 需求。

### 4.3 路径决策策略（概要）

1. 从事件/拓扑找出受影响业务（源宿、当前路径、需求）；
2. 在可用 up 链路中搜索候选路径；
3. 用静态 QoS 合成筛选满足需求的路径；
4. 优先时延低、跳数少、稳定的路径；
5. 下发后查询实际 QoS，必要时二次调整。

> **本项目实际实现**（比上述概要更严格）：规划是纯函数、下发是增量，且必须过
> Δmin 闸门——见 [闭环状态机与收敛判据](../control/闭环状态机与收敛判据.md)
> 与 [算法边界与停止条件](../../architecture/算法边界与停止条件.md)。

## 5. 两套 QoS 的接口侧差异

本节只列**接口侧**差异；**完整公式与容差以
[数学建模方案](../modeling/数学建模方案.md) §4 为唯一权威源**。

| 项目 | 实测 QoS | 静态路径 QoS |
| --- | --- | --- |
| 数据来源 | 最近 1 秒真实报文 | 候选路径链路参数 |
| 触发 | 业务运行时每秒 | 下发路径/自动重算 |
| 用途 | 页面达标/未达标 | 受理校验、选路 |
| 读取位置 | `GET /services/{id}` 的 `actual.qosMeet` | `POST .../path` 的受理判定 |

同需求阈值，不同数据源：**静态校验通过不代表实测一定达标**；实测未达标也可能是瞬时波动。

## 6. 自查与排查

```bash
# 元数据：当前任务/运行状态/场景列表
curl -sS http://localhost:10000/sdn-ui/meta | python3 -m json.tool

# 运行状态（ctrl token）
CTRL=$(python3 -c "import json;print(json.load(open('simulator/conf/gateway.json'))['ctrlToken'])")
curl -sS -H "X-Ctrl-Token: $CTRL" http://localhost:10100/api/ctrl/v1/run-info | python3 -m json.tool

# 业务实例就绪门
tail -n 20 simulator/logs/run/ui-worker.log
```

常见问题：

- 调接口 1002：检查 `X-Open-Token` 是否来自 `gateway.json` 的 `openTokens`；
- 调接口 1001：检查 `requestId`、`segments` 连续性、段类型；
- 调接口 1004：路径断开/不连通或静态 QoS 不满足，换路径；
- 事件轮询没数据：检查 `sinceTsUs` 游标，首次用 0；
- 页面卡"执行中"：看 `ui-job.json` 是否残留非 done/failed 任务，或 `ui-worker.log` 是否 `0/N ready`（需要重启 tx/rx）。

## 7. 调用计量口径（评测相关）

**观测调用分两本账**：

| 令牌 | 记到哪 | 含义 |
|---|---|---|
| `X-Open-Token`（公开令牌） | `llm_gateway_call_stat.log` | **agent 调用统计**（评测读 `GET /api/ctrl/v1/agent-calls`） |
| `X-Ctrl-Token` 或不带 | `llm_gateway_front_stat.log` | 前台调用 |

**唯一例外是改路径**：`path_event_stat.log` 硬编码 `source='agent'`，任何令牌都躲不开。

> 实践含义：agent 的每次观测都计入评测的调用量，**观测要省**——用增量轮询
> （事件游标）而非全量重拉。实现见 `src/common/perception/`。
