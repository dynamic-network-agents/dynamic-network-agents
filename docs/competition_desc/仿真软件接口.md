仿真软件接口



# 1 令牌与调用方

- Base URL：`http://{服务器IP}:10100`，公开接口前缀`/api/open/v1`；
- 令牌经请求头`X-Open-Token: {公开令牌}`携带。
- 智能体自报标识经请求头`X-Agent-Id: {agentId}`（可选，≤64字符）携带；仅用于同一队伍内多智能体实例的区分，不用于鉴权；全部调用日志记录该值（agentId字段，可空）。

# 2 通用约定

- 报文：UTF-8，HTTP+JSON；统一响应包络：

```json
{"code":0,"msg":"ok","data":{...},"time":"10:03:02.125480","tsUs":1800237782125480}
```

- 时间字段：统一为time（HH:mm:ss.uuuuuu，服务器本地时间）＋tsUs（Unix纪元微秒，整数），两个字段同源（同一时钟快照派生），全部取自仿真环境服务器时钟；
- 错误码：0成功；1001参数非法；1002令牌缺失或无效；1003资源不存在；1004状态冲突；1005触发频控；1006令牌权限不足；2000服务器内部错误。
- 幂等：提交类请求（业务路径设置、仿真运行启动）携带requestId（≤64字符）；以requestId幂等，重复提交不重复生效，都返回首次结果；requestId建议按`{agentId}-{YYYYMMddHHmmss}-{三位序号}`构造（示例性约定，不作强制）；
- 超时：客户端建议将调用超时设置为6秒；调用频控触发后返回1005，智能体应退避重试；带重试标识（请求头X-Retry-Of）的超时重传与故障自动重试不计入冗余调用；

# 4 接口定义

## GET /api/open/v1/topology 网络拓扑查询

请求：`GET /api/open/v1/topology?type=uav|ground|air`（参数可选）。

响应data：

```json
{
  "nodes": [
    {"nodeId":"UAV012","name":"无人平台12","nodeType":"uav","ip":"10.1.12.3","mask":"255.255.255.0","position":{"x":1520.0,"y":830.5},"status":"online"}
  ],
  "links": [
    {"linkId":"L00087","linkType":"microwave","srcNodeId":"GND005","dstNodeId":"AIR001","status":"up"}
  ]
}
```

说明：nodeType取值uav/ground/air（uav对应无人平台、ground对应地面节点、air对应空中节点）；linkType为链路类型英文标识（fiber=光纤、satcom=卫通、vhf=VHF、uhf=UHF、microwave=微波、5g=5G，中文名称为显示名）；status为online/offline与up/down。标识类字段一律使用英文，避免中文标识乱码。

## GET /api/open/v1/nodes 节点列表

请求：`GET /api/open/v1/nodes?type=uav|ground|air&status=online|offline`（参数可选）。

响应data：`{"nodes":[{"nodeId":"GND005","name":"地面节点5","nodeType":"ground","status":"online"}]}`，分页参数page/size可选，默认单页500条。

## GET /api/open/v1/nodes/{nodeId} 节点状态查询

响应data：`{"nodeId":"GND005","name":"地面节点5","nodeType":"ground","ip":"10.2.5.1","mask":"255.255.255.0","status":"online","time":"10:03:02.125480","tsUs":1800237782125480}`。status取值online/offline（正常/故障）。

## GET /api/open/v1/links 链路列表

请求：`GET /api/open/v1/links?nodeId={节点标识}&status=up|down`（参数可选）。

响应data：`{"links":[{"linkId":"L00087","linkType":"microwave","srcNodeId":"GND005","dstNodeId":"AIR001","status":"up","params":{"delayMs":12.5,"jitterMs":3.0,"bandwidthBps":8000000,"ber":0.0001,"packetLossRate":0.02}}]}`，分页参数page/size可选，默认单页500条。列表元素含当前链路参数，供智能体全量感知（正常规模下单页可取全量，无需逐链路查询）。

## GET /api/open/v1/links/{linkId} 链路状态查询

响应data：

```json
{
  "linkId":"L00087","linkType":"microwave","srcNodeId":"GND005","dstNodeId":"AIR001","status":"up",
  "params":{"delayMs":12.5,"jitterMs":3.0,"bandwidthBps":8000000,"ber":0.0001,"packetLossRate":0.02},
  "time":"10:03:02.125480","tsUs":1800237782125480
}
```

参数单位：delayMs/jitterMs毫秒（float）、bandwidthBps比特每秒（整数）、ber无量纲（float）、packetLossRate小数丢包率（float，0~1）。参数取值受链路类型范围约束（定义于仿真环境conf/linkTypes.json）。

## GET /api/open/v1/services 业务列表

请求：`GET /api/open/v1/services?status=running&nodeId={节点标识}`（参数可选；status可取pending/running/stopped/finished/failed）。

响应data：`{"services":[{"serviceId":"SVC0007","serviceType":"video","srcNodeId":"UAV012","dstNodeId":"UAV088","priority":6,"status":"running"}]}`，分页参数page/size可选。

## GET /api/open/v1/services/{serviceId} 业务状态查询

响应data：

```json
{
  "serviceId":"SVC0007","serviceType":"video","srcNodeId":"UAV012","dstNodeId":"UAV088",
  "requirement":{"delayMs":150,"jitterMs":30,"bandwidthBps":2000000,"ber":0.0001,"packetLossRate":0.05},
  "priority":6,"status":"running",
  "path":{"pathId":"P00031","segments":[{"type":"link","id":"L00201"},{"type":"link","id":"L00112"}]},
  "actual":{"avgDelayMs":45.2,"jitterMs":8.5,"effBwBps":1950000,"errPct":0.8,"packetLossRate":0.012},
  "time":"10:03:02.125480","tsUs":1800237782125480
}
```

status为业务状态五态（pending/running/stopped/finished/failed）；actual为最近1秒统计的实测值，字段与业务接收秒级统计同名同量纲（errPct为百分比0~100，packetLossRate为0~1小数），供智能体决策参考；业务种类枚举为data/image/voice/video。

## POST /api/open/v1/services/{serviceId}/path 业务路径设置

请求body：

```json
{"requestId":"agt01-20270118100302-001","srcNodeId":"UAV012","dstNodeId":"UAV088",
 "segments":[{"type":"link","id":"L00201"},{"type":"link","id":"L00112"},{"type":"link","id":"L00130"}]}
```

超时重传与故障自动重试经请求头`X-Retry-Of: {重试关联标识}`携带重试标识（可选，全部公开接口适用；建议取被重试请求的requestId，查询类调用可用自定标识，同一原始调用的各次重试携带同值）；带该头的调用不计入冗余调用（但计入频控与调用总数）。

响应data：

```json
{"result":"accepted","pathId":"P00032","effectiveTime":"10:03:03.010000","effectiveTsUs":1800237783010000}
```

语义（参照SR-MPLS段列表机制，段列表segments自srcNodeId起经各段至dstNodeId连续贯通）：

- type=link为邻接段：严格逐跳，路径必须使用该链路，并行链路由此区分；相邻链路段须共享端点节点；
- type=node为节点段：必经节点约束，路径必须经过该节点；节点段与其前后的端点节点或链路段之间由网络仿真按最小时延自动补齐链路，补齐链路计入路径与计分；
- result=accepted表示受理并执行，effectiveTime为服务器端生效回执时刻（策略下发时间计分终点）；rejected时附reason（1001段不存在/段类型非法/段列表不连续；1004链路断开或不连通/参数不满足业务QoS需求）；
- 纯链路段序列为标准用法（确定性最强，评测计分以此口径）。

## GET /api/open/v1/services/{serviceId}/path 业务路径查询

响应data：`{"serviceId":"SVC0007","pathId":"P00031","segments":[{"type":"link","id":"L00201"},{"type":"link","id":"L00112"}],"effectiveTime":"10:03:02.000000","source":"system"}`，source区分智能体设置与系统重算的路径；auto=true标记节点段约束下自动补齐的链路段。

## GET /api/open/v1/events 事件轮询

请求：`GET /api/open/v1/events?sinceTsUs={上次游标}&limit=100`。响应data：

```json
{
  "events": [
    {"eventId":"EVT003","type":"link_state_changed","time":"10:03:07.125480","tsUs":1800237787125480,
     "payload":{"event":"param_change","linkId":"L00087","params":{"delayMs":10.4,"jitterMs":2.6,"bandwidthBps":5600000,"ber":0.00008,"packetLossRate":0.04},"scenarioId":"sce01","instanceId":"20270118-100302","srcEventId":"EVT003"}}
  ],
  "nextSinceTsUs":1800237787125480
}
```

事件类型：node_state_changed（payload含instanceId、nodeId、state、position）、link_state_changed（payload含instanceId、linkId、event、params）、service_state_changed（payload含instanceId、serviceId、status、pathChanged）。service_state_changed的status为业务状态五态（pending/running/stopped/finished/failed）。智能体轮询间隔不大于10秒；事件按产生顺序全实例保留，sinceTsUs缺省或为0时返回全部历史事件。

事件号与来源追溯：eventId为仿真环境事件流的统一事件号——脚本事件为三位序号EVT001~EVT999（按脚本事件计划时刻升序分配，同刻按脚本文件内数组序，结果可复算；单个脚本事件总数不超过999条，一次测试只运行一个脚本），节点移动逐点派生的链路/节点事件与对外事件流对应事件的eventId一律取触发移动的脚本事件号（如节点移动脚本事件EVT003逐点派生的链路事件，eventId均为EVT003），接口与人工操作产生的运行期事件自EVT1000起自增；srcEventId仅在事件由脚本事件派生时携带，值为触发它的脚本事件号，脚本事件自身的事件不携带srcEventId。

## GET /api/open/v1/time 服务器时间

响应data：`{"time":"10:03:02.125480","tsUs":1800237782125480}`，供智能体校时与计时对齐。

## POST /api/open/v1/simulation/start 仿真运行启动

请求body：`{"requestId":"agent1-20270118100302-001","suiteId":"sce20261104-conf01","scenarioId":"sce01","scriptId":"script-01"}`。一次测试实例运行一个脚本：suiteId/scenarioId/scriptId 分别指定场景套件、场景实例与所加载脚本，三者缺一返回1001；同requestId重复提交不重复启动、返回首次结果。

响应data：`{"result":"started","suiteId":"sce20261104-conf01","scenarioId":"sce01","scriptId":"script-01","instanceId":"20270118-100302","t0Time":"10:03:02.000000","t0TsUs":1800237782000000}`。instanceId 标识本次测试实例；t0Time/t0TsUs 为测试开始时刻（T0），脚本事件 `time` 与业务 `startAtSec` 均相对T0计；启动后事件按脚本时序生效，业务路径设置与事件轮询接口即以该实例为上下文。
