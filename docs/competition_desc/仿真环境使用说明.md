# 仿真环境使用说明

# 一、概述

本说明面向参赛队，介绍随赛题交付的仿真环境与测评软件的能力构成与使用方法。交付内容：

- `simulator/`：仿真环境（场景库、生成工具链、全局配置、素材、日志目录）；
- `doc/`：《仿真软件接口》；
- `.agents/skills/scenario-gen/`：场景生成技能（供你的开发辅助agent加载使用）。

**参赛方工作目录＝发布包根目录**，下文所有相对路径均以此为基准。

交付环境中你直接使用两样东西：**仿真环境**提供界面与API——界面用于查看场景、启动仿真测试、观察网络与业务的实时状态，智能体经API获取网络与业务状态并下发控制；**测评软件**提供界面，测试与评分结果在其界面查看。

仿真环境提供四方面能力：

1. **场景库**：预置场景套件（命名`sce<YYYYMMdd>-<配置集后缀>`，如`sce20261008-conf01`），每套件含若干场景实例（`sce<两位序号>`），每实例含初始拓扑、初始业务与n个难度递进的脚本（`script-01~n`）。场景以无人集群通信网络为对象，通过脚本事件（节点下线/移动、链路中断/劣化、业务调整）构造动态扰动，考验资源管控智能体的重路由与业务保障能力。
2. **场景数据与可复现性**：场景全部为json文件。
3. **场景生成工具链**：`simulator/gen_scripts/`下的生成器、绘图与场景统计工具，可从配置集（`data/gen_conf<NN>/params.yaml`，只含场景规模与事件时间参数；生成逻辑默认参数在同目录`gen_internal.yaml`）生成你自己的场景套件；`.agents/skills/scenario-gen/`技能定义了交互式生成流程。
4. **接口**：智能体经HTTP接口获取网络/业务状态并下发控制，全部约定以`doc/仿真软件接口.md`为准。

运行环境基线：Ubuntu 22.04.5，Python 3.12+（Java 21+/PyTorch 2.10+/Spring AI 2.0+，详见赛题发布清单）。

# 二、目录结构

```
（发布包根）/
├─ simulator/
│  ├─ conf/linkTypes.json        # 全局链路类型能力范围（带宽/时延/抖动/误码率/丢包率的允许区间，唯一来源）
│  ├─ gen_scripts/               # 场景生成工具链（生成件，未经许可不得修改）
│  │   gen_scenarios.py / plot_topo.py / plot_services.py / export_scenario_stats.py
│  ├─ data/
│  │   ├─ gen_conf<NN>/          # 配置集（params.yaml：场景规模与事件时间参数；生成逻辑默认参数在 gen_scripts/gen_internal.yaml）
│  │   ├─ scenarios/<套件>/<实例>/  # 场景库：net-topo.json、bg-service.json、scripts/、<场景标识>-stats.md（场景统计）
│  │   └─ figures/<套件>/<实例>/    # 辅助图（拓扑图/业务关系图/事件图），场景生成时产出，仅供人工查看，不是仿真输入
│  ├─ assets/                    # 业务素材目录，素材随包提供，可按格式替换、补充（见第2节步骤2）
│  ├─ logs/                      # 运行日志落盘目录（按 套件/场景/脚本/实例 分层）
│  ├─ docker/                    # 容器化部署编排：netsim、servicesim/tx、servicesim/rx、eval 各自的 compose.yml 编排
│  └─ images/                    # 各模块镜像归档与 load-images.sh 加载脚本
├─ doc/                          # 仿真软件接口.md、仿真环境使用说明.md
└─ .agents/skills/scenario-gen/  # 场景生成技能（SKILL.md+参数清单+校验脚本）
```

# 三、使用说明

## 1：环境要求

- ubuntu22.04 desktop x64。
- Python 3.12。
- docker 26+, docker-compose 1.29+。
- 服务器1台：网络仿真、业务仿真发送端、业务仿真接收端、测评软件四个模块全部部署在这台服务器上，下文全部操作都在该服务器上完成。

## 2：部署与启动仿真环境

发布包解压到服务器即可，包内 `simulator/` 目录即数据根。部署后仿真环境与测评软件作为常驻服务运行，开发调试期间可反复发起测试。

- **使用方法**：

  1. 解压发布包：解压到部署目录，例如主目录下的~/simulator。

  2. 核对业务素材：数据根assets/各子目录已随包提供业务测试素材——assets/image/存放图片文件（bmp、png），assets/voice/存放话音文件（wav），assets/video/存放视频文件（mp4、avi），assets/data/存放预制数据（格式不限）。可直接使用，也可按同样格式替换或补充文件（文件名与数量自定）；媒体类业务经bg-service.json的media.dir引用这几个目录，发送端按文件名顺序循环读取。

  3. 加载镜像：`cd 数据根/images && ./load-images.sh`，加载四个模块的镜像归档，全部加载成功输出"全部镜像加载完成"。

  4. 启动仿真环境：依次进入`数据根/docker/netsim`、`数据根/docker/servicesim/tx`、`数据根/docker/servicesim/rx`执行`docker compose up -d`。

  5. 启动测评软件：`cd 数据根/docker/eval && docker compose up -d`。

  6. 配置大模型网关：大模型调用必须经过大模型网关，智能体使用测评程序代理出的大模型接口，使用方法见`docker/eval/readme.md`。

  7. 访问：浏览器打开界面——仿真环境`http://localhost:10000`、测评软件`http://localhost:10010`（从网络内其他机器访问时把localhost换为该服务器IP）；智能体API为`http://localhost:10100/api/open/v1`，接口语义见`doc/仿真软件接口.md`。

  8. 停止与重启：进入对应目录执行`docker compose down`停止，重新启动仍执行`docker compose up -d`。

## 3：读场景库README

- 每个场景套件根目录的README.md是该套件的完整说明书：场景清单表（规模/链路/业务/事件数）、事件模型（时间窗口、簇结构、难度公式）、脚本事件格式与字段说明、规模边界说明。
- 套件内场景从易到难排列，场景决定网络拓扑规模，规模越大越难；场景内脚本也从易到难，脚本决定事件难度，编号越靠后事件越密集、链路劣化越重。先易后难：从`sce01`开始，同一实例内`script-01`最易。

## 4：启动仿真

- 方法1：进入仿真环境界面`http://localhost:10000`，选择场景套件、场景、脚本，点击启动。
- 方法2：调用仿真运行启动接口。响应返回本次测试实例标识instanceId与测试开始时刻t0Time/t0TsUs（T0）；同requestId重复调用不重复启动：

  ```bash
  curl -X POST http://localhost:10100/api/open/v1/simulation/start \
    -H "Content-Type: application/json" -H "X-Open-Token: <公开令牌>" \
    -d '{"requestId":"c-20261104-001","suiteId":"<场景套件>","scenarioId":"<场景实例>","scriptId":"<脚本>"}'
  ```

- 启动后事件按脚本内`time`字段（相对测试开始时刻T0的秒数）依序生效；智能体经事件轮询接口感知事件并响应（见第7节）。

## 5：场景

- 每个场景实例目录含三类数据文件：
  - `net-topo.json`：初始拓扑。顶层含`area`（场景区域宽/高，米，节点坐标上界）；节点含标识/类型/坐标/IP；链路含`linkType`与`params`（delayMs、jitterMs、bandwidthBps、ber、packetLossRate）。
  - `bg-service.json`：初始业务。`category`区分背景业务（background）与测试业务流（test）；`requirement`为QoS上限（时延/抖动/误码率/丢包率）与带宽下限；媒体类业务经`media.dir`引用assets素材。需求与链路参数均为工程档位数值（时延5ms档、抖动整数ms、速率2位有效、丢包/误码1位有效），公式判定即按这些值。
  - `scripts/script-NN.json`：场景脚本，json列表，每项含`time`（相对T0秒）、`eventType`、`attrs`。
- 数据满足的不变式，可依赖：
  - 链路参数一律落在`conf/linkTypes.json`该链路类型的范围内；丢包率`packetLossRate`为0~1小数（非百分比）；
  - 视距类链路（vhf/uhf/microwave/5g）仅存在于距离＜40km的节点对之间；距离≥40km只可能是光纤/卫通；
  - 地面节点间链路类型2~5种、空-地链路类型2~5种；跨视距互联的地面节点对同时具备光纤与卫通双手段；
- 事件类型：`node_offline/node_online`（节点下线/上线）、`node_move`（节点移动）、`link_param_change`（参数劣化，范围仍受linkTypes约束）、`link_state`（链路中断/恢复）、`service_adjust`（新增业务）。每条脚本末尾另有 `stop` 测试结束标记，到点由仿真自动结束实例，智能体无需处理。
- 每场景的`<场景标识>-stats.md`是场景统计，四节＝**概览**（节点/链路/业务/脚本总量与多视角汇总）、**节点统计**（按uav/gnd/air小节，逐节点链路总数与分类链路汇总）、**链路统计**（按uav-gnd/gnd-air/gnd-gnd小节，逐节点对先总数再编号列举每条链路，含按链路类型汇总与参数范围）、**业务统计**（按业务类型小节，逐业务属性、QoS需求、路径统计与业务路径）。分T0初始选定路径（链路参数为net-topo基线）与事件末态选定路径（逐脚本全部事件生效后的末态拓扑，链路参数取末态快照）。每路径给出逐跳链路参数表（带宽/时延/抖动/丢包率/误码率）、端到端QoS合成公式的代入计算（LaTeX表达）与对业务需求的逐项满足性判定。事件使路径不可达时，以当前拓扑重新搜索可用路径。

## 6：生成自己的场景套件

推荐用开发辅助agent加载`.agents/skills/scenario-gen/`技能，对它说明生成需求即可：技能逐项与你确认下列参数（每项有默认值，可直接采用），确认后生成并自动复验证。也可直接编辑params.yaml手工生成。

- 场景个数、每场景脚本数：决定套件规模与难度阶梯；
- 网络区域尺寸、每簇地面节点数：网络布设形态，地面节点按地理聚集分簇；
- 无人平台（业务节点）、地面节点、空中节点、链路总数、背景业务、测试业务的数量范围：网络与业务规模，越大越难；
- 单次测试时长、事件窗口、簇内事件间隔、簇间事件间隔：事件节奏。事件窗口指事件允许发生的时间段，以相对测试开始时刻T0、测试结束时刻Tend的偏移表达，默认T0+3分钟~Tend-4分钟，首尾留纯净时段便于测前状态确认与测后结算；改窄可能导致仿真不收敛。

手工生成命令：

```bash
cd simulator/gen_scripts
# 1) 新建配置集：复制 data/gen_conf01/params.yaml 到 data/gen_conf<新序号>/，按需改值
# 2) 生成：
python3 gen_scenarios.py --conf gen_conf<新序号>          # → data/scenarios/sce<YYYYMMdd>-conf<新序号>/
# 3) 复验证（必须全绿，末行"全部通过 ✓"）：
python3 ../../.agents/skills/scenario-gen/scripts/validate_library.py --conf gen_conf<新序号>
# 4)（可选）辅助图与场景统计：
python3 plot_topo.py ../data/scenarios/<新套件>/sce*
python3 plot_services.py --split ../data/scenarios/<新套件>/sce*
python3 plot_events.py ../data/scenarios/<新套件>/sce*
python3 export_scenario_stats.py ../data/scenarios/<新套件>/sce*
```

## 7：接口

智能体经公开接口观测网络状态、下发控制指令，形成"感知—决策—执行"闭环。接口清单、报文格式、错误码与调用频控见`doc/仿真软件接口.md`。
