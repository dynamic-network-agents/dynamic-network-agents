# 问题清单与问题记录模板

> 用途：统一登记开发、调试和实验过程中发现的问题。问题创建时优先从当前实验上下文自动填充信息；问题分析和结论由研发人员确认。

## 1. 问题总清单

建议由问题管理工具自动维护本表。每个问题的详细内容单独保存为
`ISS-xxxx.md`。

  ------------------------------------------------------------------------------------------------------------
  问题编号   标题                                 分类       优先级     状态       首次发现实验   创建时间
  ---------- ------------------------------------ ---------- ---------- ---------- -------------- ------------
  ISS-0001   示例：链路中断后业务路径未及时切换   ALG        P1         open       EXP-0001       YYYY-MM-DD

  ISS-0002   `待填写`                             `待填写`   `待填写`   `待填写`   `待填写`       `待填写`
  ------------------------------------------------------------------------------------------------------------

### 1.1 分类

  --------------------------------------------------------------------------------------------------------
  分类代码                分类名称                典型问题
  ----------------------- ----------------------- --------------------------------------------------------
  ENV                     工程环境类              环境部署、Docker、启动停止、配置、依赖、日志、性能资源

  NET                     通信网络模型类          拓扑、节点状态/移动、链路状态/参数、连通性、事件感知

  ALG                     资源管控算法类          QoS、路径搜索、路由优化、多业务联合优化、重路由稳定性

  AGT                     Agent 智能体类          架构、感知、决策、工具调用、多 Agent
                                                  协同、模型/RAG/Skill

  EXP                     实验评测类              场景、复现、指标统计、异常分析、算法对比、实验性能
  --------------------------------------------------------------------------------------------------------

### 1.2 优先级

-   P0：阻断核心开发或实验，当前无法继续；
-   P1：核心功能异常或显著影响实验结果；
-   P2：一般缺陷，有可行绕行方案；
-   P3：体验、文档或低影响问题。

### 1.3 状态

-   `open`：新建，尚未处理；
-   `investigating`：正在排查；
-   `blocked`：受外部条件阻塞；
-   `fixing`：已有原因，正在修复；
-   `verifying`：修复后验证中；
-   `resolved`：已验证解决；
-   `closed`：问题关闭；
-   `reopened`：已解决后再次出现。

## 3. 自动关联规则

第一阶段按以下规则执行：

  ---------------------------------------------------------------------------------------------
  场景                               自动化行为                         是否需要人工确认
  ---------------------------------- ---------------------------------- -----------------------
  创建问题时存在有效当前实验上下文   自动建立 `discovered_in` 关系      不需要，用户可修改

  同一实验定义中再次发现同类问题     推荐已有问题，提示可能重复         需要

  同一场景不同脚本出现相似问题       根据场景、模块、标签和关键词推荐   需要

  不同场景出现相似问题               根据模块、标签和关键词推荐         需要

  修复后在新实验中验证               建议建立 `verified_in` 关系        需要确认验证结论

  已解决问题再次出现                 提示可能回归，建议 `regression_in` 需要
  ---------------------------------------------------------------------------------------------

### 3.1 自动推荐应保存的信息

-   候选问题编号；
-   匹配依据（相同场景、相同模块、标签重合、关键词重合等）；
-   匹配分值或置信等级；
-   推荐时间；
-   是否由人工确认；
-   确认人及确认时间（如有）。

自动推荐不能直接把两个问题合并，也不能未经确认将"相似"写成"同一根因"。

## 4. 问题清单维护约定

1.  一个独立问题使用一个唯一编号和一份详细记录。
2.  问题标题描述现象或目标，不把未经验证的猜测写入标题。
3.  一个问题可以关联多个实验；一个实验也可以关联多个问题。
4.  同一问题在不同实验中复现时，优先追加关联，不重复创建问题。
5.  只有现象或根因确实不同，才拆分为不同问题。
6.  解决问题必须记录验证实验或明确说明无法验证的原因。
7.  关闭问题前应填写根因、修复措施和验证结论；暂时无法确认的内容明确标注。
8.  原始日志和大体积附件可放在独立附件目录，问题记录保存相对路径和必要摘要。
9.  不记录令牌、密钥、密码或其他敏感配置。
10. 问题索引和关系索引由工具维护，避免多人手工编辑造成编号冲突。
