无人平台组网设计方案

面向「资源受限环境下通信网络资源管控」竞赛：无人平台的组网方式、链路建立、资源分配调度、数据传输，以及可参考的协议标准与成熟方案。

1. 无人平台概述

无人平台（Unmanned Platform / Unmanned System）：不搭载机上操作人员、可自主或遥控执行任务的装备/载具。在通信网络语境下，它是网络中的机动节点（mobile node），通过无线链路接入机动通信网络，向指挥/协同节点回传数据和接收指令。

类型名称典型任务
空中无人机（UAV）侦察、测绘、中继、打击
地面无人车（UGV）巡逻、运输、排爆
水面无人艇（USV）巡逻、探测、反潜
水下无人潜航器（UUV/AUV）探测、布雷、水下中继

关键背景：无人平台处于高速机动、高动态拓扑、窄带宽、强干扰环境下，链路随机通断、带宽动态收缩，因此通信网络需要从"人工配置、中心调度"转向"分布式、自感知、自决策、自协同"的智能化自治模式。

链路质量五要素（对应赛题链路参数模型）：delayMs（时延）、jitterMs（抖动）、bandwidthBps（带宽）、ber（误码率）、packetLossRate（丢包率）。

业务类型与 QoS 门槛：

业务类型QoS 敏感点
话音时延、抖动敏感
视频带宽敏感
数据丢包敏感
图片带宽 + 可靠性

2. 组网方式：分级混合 + 控制/数据面分离

无人平台组网不是单一模式，而是在三种基本形态之上，针对"高机动 + 资源受限 + 抗毁"需求演化出的分级混合式。核心结论：

数据面分布式自组网 + 管控面分层协调（协调器统一编排、仲裁，支持降级自治）

2.1 三种基本组网形态

组网方式结构决策方式典型实例优点缺点
集中式（有中心）星型/树型，节点统一连中心基站/AP中心统一调度蜂窝网（基站）、IEEE 802.11 基础设施模式资源分配集中高效、接入管理简单、QoS 可控单点故障、抗毁性差、覆盖受限、不适应高速机动节点
分布式自组网（Ad Hoc / MANET）无中心、对等多跳各节点本地决策AODV（RFC 3561）、OLSR（RFC 3626）、IEEE 802.11 ad-hoc / 802.11s mesh抗毁强、即插即用、拓扑自适应、适合机动路由/控制开销大、容量受限、全局优化困难
分级/分层混合式（分簇）簇头 + 簇成员，骨干 + 接入簇头局部协调 + 骨干全局协调分簇路由（如 LEACH/HEED 思想）、战术数据链分层组网兼顾抗毁与效率、扩展性好簇头选举/维护有开销、簇头成为局部关键节点

形态选择的分析：

  • 纯集中式不可行：无人平台高速机动、链路随机通断，中心链路一旦中断全网失联；且中心基站覆盖受限，无法跟随平台机动。
  • 纯分布式在窄带宽下开销过大：资源受限（窄带宽）场景下，分布式路由的洪泛/控制报文开销占比高，且缺乏全局视图，难以做带宽、路由的全局优化和冲突仲裁。
  • 分级混合是折中：数据面用分布式自组网保证抗毁与自愈，管控面用分层协调保证全局优化与冲突仲裁，是军用机动通信的成熟思路（参考 Link 16/TTNT 的分层组网理念）。

2.2 控制面与数据面分离

借鉴 SDN（软件定义网络，OpenFlow/ONF） 的"控制与转发分离"思想，但不是照搬集中式 SDN 控制器，而是适配无人平台场景的"分布式数据面 + 分层/半集中管控面"：

层面模式职责成熟技术
数据面（连通 + 转发）分布式为主邻居发现、多跳转发、拓扑自愈MANET 路由（OLSR/AODV）、DTN 存储转发
管控面（决策 + 仲裁）分层、可降级态势汇总、资源优化、冲突仲裁、策略校验协调器 Coordinator + 策略中心

协调器 ≠ 数据必经中心：协调器是管控面的编排者（任务调度、冲突仲裁、策略校验），业务数据流不经过协调器，底层数据转发仍由分布式路由完成。协调器只下发"策略"（路由、带宽、优先级），不转发"数据"。

降级自治机制（抗毁关键）：协调器是"逻辑协调中心"而非"物理唯一中心"。当协调器或骨干链路被毁，系统应能逐级降级：

  1. 协调器失效 → 区域簇头/汇聚节点临时接管本区域协调；
  2. 簇头也失效 → 退化为预置规则 + 节点本地自治（按固化优先级、最短路径规则运行）；
  3. 链路恢复 → 重新选举/上报，恢复全局协调。

这一"可降级、可替换"设计是无人平台网络抗毁性的核心，也是赛题"从中心调度转向自协同"的落地体现。

2.3 自组织网络（SON）思想

3GPP 定义的自组织网络（Self-Organizing Network, SON）三大能力，与赛题理念一一对应：

SON 能力含义赛题对应
自配置（Self-Configuration）节点即插即用、自动入网、自动获取参数分布式组网、邻居发现
自优化（Self-Optimization）自动调路由/带宽/功率等参数自决策、资源动态调度
自愈（Self-Healing）故障自动检测与恢复自感知、故障诊断、自愈建议

无人平台组网可视为 SON 思想在"高动态、抗毁、资源受限"场景下的强化版本。

3. "分布式、自感知、自决策、自协同"的工程化落地

四个理念不是口号，每一项都能落到具体机制与协议上。关键区分："分布式/自感知"主要在数据面（用成熟网络协议实现），"自决策/自协同"主要在管控面（用多智能体 + 确定性算法实现）；LLM 只负责意图理解、故障解释、工具选择，不直接跑路由协议、不做精确数值计算。

3.1 分布式：去中心化组网与决策

机制技术手段说明
邻居发现HELLO 报文周期广播节点周期广播自身 ID、位置、序列号，收到应答即建立邻居关系
分布式路由（主动式）OLSR（RFC 3626）/ OLSRv2（RFC 7181）周期洪泛链路状态，全网维护一致拓扑视图，低时延
分布式路由（反应式）AODV（RFC 3561）有数据才发起路由发现（RREQ/RREP），省开销
分簇LEACH、HEED 等分簇算法节点聚簇、簇头局部协调，降低全局控制开销
去中心化决策每节点本地计算下一跳用 Dijkstra/K 最短路本地算路，无需全局控制器

3.2 自感知：网络状态与频谱感知

感知维度技术手段赛题映射
邻居/拓扑感知HELLO 信标、链路状态通告（LSA）、全网快照拓扑感知、连通分量分析
链路质量感知ETX（期望传输次数，De Couto 等 2003）、SNR、RSSI、误码率、丢包率ber、packetLossRate、delayMs、jitterMs
频谱/干扰感知认知无线电、频谱扫描、干扰检测、动态频谱接入（IEEE 802.22 WRAN）强干扰场景下的自适应换频/跳频
异常感知阈值规则 + 时序异常检测故障诊断、异常事件检测

其中 ETX 是自组织网络最常用的链路代价度量：ETX = 1 /（正向成功投递率 × 反向成功投递率），可由误码率、丢包率换算而来，直接作为路由权重，使算法"感知"链路质量。这是把赛题的链路五要素接入路由决策的关键桥梁。

3.3 自决策：本地路由 + 智能体策略

决策分两个层次，各司其职：

层次决策主体决策内容技术
本地（数据面）每个节点下一跳选择、本地转发分布式路由 + Dijkstra/K 最短路
全局（管控面）运维 Agent → 资源 Agent → 协调器故障定位、候选路由、带宽分配、QoS 优先级LLM 意图理解 + OR-Tools/NetworkX 确定性算法 + 策略校验

LLM 的定位边界（赛题评分点 2.3 的关键）：LLM 负责解析业务约束、解释故障、判断调用哪类工具、生成规范的工具调用参数、总结决策依据；不负责精确算最短路径/最大流/带宽分配（这些由确定性算法保证可复现、可校验），不绕过策略校验直接改网络状态。

3.4 自协同：冲突仲裁与协作传输

协同机制技术手段说明
资源冲突仲裁优先级调度、多维资源加锁、快照版本校验多业务争用链路时按优先级/最低保障带宽分配
资源协商博弈论、拍卖/竞价机制分布式频谱/带宽竞价，避免互相抢占
协作传输多路径并行、协作分集、中继协作提高可靠性与吞吐
Agent 协同A2A 消息（运维 ↔ 资源 ↔ 协调器）交换诊断结果、约束、候选策略

3.5 四者闭环

"分布式、自感知、自决策、自协同"构成一个闭环，对应赛题要求的"状态采集 → 异常识别 → 故障诊断 → 资源评估 → 策略生成 → 策略校验 → 策略下发 → 效果反馈 → 再评估"：

自感知（采集/诊断）
   │ 态势 + 约束
   ▼
自决策（本地路由 + 智能体生成策略）
   │ 候选策略
   ▼
自协同（冲突仲裁 + 校验 + 协作传输）
   │ 已校验策略下发 + 执行反馈
   ▼
分布式数据面执行 → 再自感知（闭环）

4. 组网分层与节点角色

无人平台网络是典型的"接入网 — 中继层 — 骨干网"三层结构，各层职责、带宽、机动性不同。

        ┌───────────── 骨干网 (Backbone) ─────────────┐
        地面站/指挥所 ◄──高带宽微波/卫星──► 卫星/预警机
                     │                    │
        ┌────────────▼──── 中继层 (Relay) ────────────┐
        中继机/中继节点（多跳转发、扩展覆盖、绕视距遮挡）
                     │                    │
        ┌────────────▼──── 接入网 (Access) ───────────┐
        末端无人平台（UAV/UGV/UUV，单跳或多跳接入）

4.1 三层结构详述

层次组成链路特点主要功能
接入网（Access）末端无人平台近距离、带宽较小、机动性强、链路断续业务产生/接收、单跳或多跳接入中继/骨干
中继层（Relay）中继机、升空平台中距、承上启下、需覆盖/绕遮挡多跳转发、扩展覆盖、克服视距遮挡、延伸接入范围
骨干网（Backbone）地面站、预警机、卫星终端高带宽、长距、相对稳定跨区域互联、上联卫星/指挥所、承接大容量回传

层次间关系：接入层末端平台先接入最近的中继节点，中继节点逐跳把数据汇聚到骨干节点，再由骨干网通过微波/卫星链路送抵地面指挥所/卫星。带宽自接入层向骨干层逐级增大，机动性自骨干层向接入层逐级增强。

4.2 节点角色与功能

角色职责典型载体
普通节点（member）业务源/宿，接入网络末端无人机、无人车
中继节点（relay）多跳转发、扩大覆盖、克服遮挡中继机、升空平台
簇头/汇聚节点（cluster head / sink）区域内局部协调、数据汇聚、临时接管区域中心节点
骨干节点/网关（backbone / gateway）跨区域互联、上联卫星/指挥所、异构网互联地面站、预警机、卫星终端
指挥控制节点（C2）全局态势汇总、任务下达指挥所、地面站

4.3 层次间的链路建立与入网/退网

链路建立遵循"邻居发现 → 质量测量 → 拓扑建立 → 路由计算"四步（详见第 5 章），层次间连接的核心动作：

  1. 接入选择：末端平台入网时广播接入请求，选择信号最强/路径最优的邻近中继或簇头接入。
  2. 中继建立：中继节点之间以及中继到骨干之间建立转发路径，形成多跳链。
  3. 骨干上联：骨干节点通过微波/卫星链路与地面站、卫星建立高带宽回传。
  4. 入网/退网：节点上线广播 → 拓扑更新（链路状态通告）→ 触发路由重算 → 智能体感知连通度变化 → 生成替代路径/自愈建议。

4.4 分簇与簇头机制

分级混合组网中，分簇是控制开销、提升扩展性的关键手段：

分簇算法来源思想
LEACHHeinzelman 等，2000（WSN 经典）簇头轮换、簇内单跳，均衡能耗
HEEDYounis & Fahmy，2004混合分布式分簇，考虑剩余能量与通信代价

无人平台场景可借鉴其"簇头轮换 + 簇头降级"思想：簇头不是固定节点，可轮换选举，簇头失效时成员重新选簇头，避免单点故障。

4.5 与赛题节点/链路的对应

赛题样例数据中 GND（地面）→ AIR（空中）的 microwave（微波）链路，正对应"骨干/地面指挥节点 ↔ 空中中继/机动节点"的骨干-接入关系。链路类型字段 linkType 可扩展为 microwave（微波）、satellite（卫星）、vhf/uhf（超短波）等，对应本章的骨干、中继、接入各层。

5. 链路建立过程

一条链路从"节点开机"到"可承载业务"，遵循"邻居发现 → 链路质量测量 → 拓扑建立 → 路由计算 → 链路维护/失效处理"的完整生命周期。本节按此展开，并给出每步对应的协议标准与赛题落地。

5.1 总体流程

节点开机/入网
   │ ① 邻居发现（HELLO 广播 + 握手）
   ▼
链路质量测量（RSSI/SNR/BER → ETX 代价）
   │ ② 生成链路代价，作为路由权重
   ▼
拓扑建立（主动式洪泛 / 反应式按需探测）
   │ ③ 形成全网或局部拓扑视图
   ▼
路由计算（Dijkstra / K 最短路 / CSPF）
   │ ④ 确定下一跳 / 候选路径
   ▼
链路维护（周期性探测 + 失效检测 + 重路由）

5.2 邻居发现（Neighbor Discovery）

机制说明标准/来源
HELLO 报文周期广播节点周期广播自身 ID、位置、能力、序列号，收到即确认邻居OLSR 的 HELLO 消息（RFC 3626）
双向/三向握手通过应答区分单向链路与双向链路IPv6 邻居发现（RFC 4861）类比
失效判定连续若干周期未收到 HELLO，判定邻居失效定时器超时机制

要点：

  • HELLO 报文携带节点唯一标识、位置、移动性信息、当前时间，为后续链路测量和拓扑建立提供原始输入。
  • 只有确认双向可达的邻居才纳入路由计算，避免单向链路的"隐藏终端"问题。
  • 邻居表维护有效期（lifetime），超时未刷新即删除，对应赛题"节点下线"的自动感知。

5.3 链路质量测量（Link Quality Measurement）

链路质量是路由决策的核心输入，分物理层原始指标和链路层综合代价两层：

指标含义来源
RSSI接收信号强度物理层
SNR信噪比物理层
BER误码率物理层，赛题字段 ber
丢包率数据包丢失比例链路层，赛题字段 packetLossRate
时延/抖动端到端时延、抖动赛题字段 delayMs、jitterMs

ETX（期望传输次数，Expected Transmission Count） 是最常用的综合链路代价（De Couto 等，2003）：

ETX = 1 /（正向投递率 df × 反向投递率 dr）
  • df = 1 − 正向丢包率，dr = 1 − 反向丢包率（可由 packetLossRate、ber 换算）。
  • ETX 越小链路越好，作为 Dijkstra 等最短路算法的边权，让路由"感知"链路质量。
  • 进一步引入 ETT（期望传输时间，Draves 等，2004），把带宽也纳入代价：ETT = ETX ×（平均包长 / 链路带宽），对应赛题 bandwidthBps。

赛题落地：把链路五要素（delayMs/jitterMs/bandwidthBps/ber/packetLossRate）加权合成一个综合代价（如 ETX 或 ETT），作为 NetworkX 图上的边权，即可实现"链路质量感知路由"。

5.4 拓扑建立（Topology Establishment）

按信息获取方式分三类路由协议的拓扑建立机制：

类型机制代表协议适用
主动式（表驱动）周期洪泛链路状态，全网维护一致拓扑OLSR（RFC 3626）、OLSRv2（RFC 7181）、OSPF（RFC 2328）类比密集、低时延要求
反应式（按需）有数据才发起路由发现（RREQ/RREP）AODV（RFC 3561）、DSR（RFC 4728）稀疏、流量少
混合式区域内主动 + 区域间反应ZRP大规模分层

关键机制：

  • 链路状态通告（LSA）：主动式协议中，节点把与邻居的链路状态洪泛给全网，各节点拼出全网拓扑图（OSPF 的 LSA 思想，RFC 2328）。
  • MPR（多点中继）：OLSR 用于减少洪泛冗余的机制——每个节点只选少量邻居作为中继转发控制报文，降低控制开销，适合窄带宽场景（RFC 3626）。
  • 按需路由发现：AODV 中源节点广播 RREQ，目标/中间节点回 RREP，沿途建立反向/正向路由，不维护全网拓扑，省开销。

赛题落地：仿真层可用"全网快照 + NetworkX 连通分量分析"简化实现主动式拓扑建立；动态场景下用事件驱动触发重算，模拟反应式的按需更新。

5.5 路由计算（Route Computation）

拓扑视图建立后，用图算法计算转发路径：

算法用途来源
Dijkstra单源最短路Dijkstra 1959，O((V+E) log V)
Bellman-Ford含负权/分布式距离向量距离向量协议（Babel，RFC 6126）
K 最短路（Yen）多候选路径，供故障切换Yen 1971
CSPF（约束最短路）带带宽/时延/丢包约束的路径选择MPLS-TE（RFC 3209）思想

关键区分：

  • 分布式：每节点本地算下一跳（Dijkstra/距离向量），对应数据面。
  • 集中式辅助：由 Python 算法服务算 K 条候选路径 + CSPF 约束过滤，返回给智能体，对应管控面（方案中的算法层）。

5.6 链路维护与失效处理（Link Maintenance）

链路是动态的，建立后仍需持续维护：

机制说明赛题对应
失效检测连续若干 HELLO 周期未收到，判定链路中断异常事件检测
局部修复AODV 在断链处就近重路由，避免全局重算替代路径生成
拓扑更新链路状态变化洪泛全网，触发重算拓扑快速变化场景
自愈建议智能体基于诊断结果生成恢复策略自愈建议生成

赛题落地：链路中断（status 变 down / 丢包率突增）→ 运维 Agent 感知 → 资源 Agent 计算替代路径 → 策略校验 → 下发 → 反馈，构成一个完整的故障恢复闭环。

7. 数据传输

  • 多跳转发：源 → 中继 → 骨干逐跳传递。
  • 断续链路容错：链路随机通断时用容迟容断（DTN）"存储-转发"，等链路恢复再传（对应赛题"链路断续多发"）。
  • 协同传输：多路径并行、协作分集，提高可靠性和吞吐。

9. 落地建议（仿真实现）

数据面采用 MANET 分布式自组网（OLSRv2 + AODV 混合，参考 TTNT/Link 16 设计理念），管控面采用多智能体（运维 Agent + 资源控制 Agent + Coordinator 协调仲裁），控制面与数据面分离，支持中心降级自治；断续链路用 DTN 存储转发兜底。

仿真环境无需实现完整协议栈，建议：

  1. 用 NetworkX 的连通分量 / 最短路径 / K 最短路 简化实现"分布式路由"效果；
  2. 用链路代价 ETX（由误码率、丢包率换算）作为路由权重，让算法"感知"链路质量；
  3. 带宽分配用 OR-Tools 线性/整数规划，QoS 用 DiffServ 式优先级队列建模；
  4. 文档中明确"参考 TTNT/Link 16/OLSRv2 标准，仿真层做协议简化"。
