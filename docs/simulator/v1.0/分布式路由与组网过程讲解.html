分布式路由与组网过程讲解

面向熟悉 4G/5G 接入网、但对 mesh/自组网不熟的读者：用一个具体例子，讲清楚自组网怎么组网、网络拓扑怎么建立/保存/维护、路由表到底存什么、"目的地"是什么、数据怎么逐跳转发。

1. 先建立心智模型（用 4G/5G 做锚点）

4G/5G 是「有固定中心、集中式」：终端(UE) 永远接入基站(gNB/eNB)，基站由核心网(AMF/MME)统一管。有"基站—终端"的主从之分，网络拓扑是固定的（基站不动、预先规划）。

Mesh/自组网是「无固定中心、分布式」：每个节点既是"终端"又是"基站"，节点之间互相发现、互相转发，拓扑随时在变，没有谁天生是中心。

概念4G/5G（熟悉的）Mesh/自组网（本方案）
谁发现谁基站广播 SIB/SSB，UE 搜小区人人广播 HELLO，互相发现（无主从）
接入方式UE 单跳 attach 到基站节点接入邻居，可多跳转发
谁管拓扑核心网 AMF/MME（集中）每节点本地维护 + 协调器全局汇总
谁算路由核心网/基站（集中）每个节点本地算下一跳（分布）
节点移动切换基站(handover)换邻居 + 重路由

一句话记住：蜂窝网是"大家连基站"，自组网是"大家连大家"。

2. 一个具体场景（先约定节点）

约定一个无人平台任务网，节点如下：

节点类别层次作用
C协调器管控面全局调度、仲裁（地面指挥所）
B1骨干节点骨干网地面站，微波连 C
R1、R2中继节点中继层中继机，转发+扩覆盖
U1、U2末端平台接入网侦察 UAV
G1、G2末端平台接入网UGV 无人车

目标拓扑（最终形成的样子）：

             C (协调器/指挥所)
             │
             B1 (骨干/地面站)
             │
        ┌────┴────┐
       R1(中继)   R2(中继)
       /  \        /  \
     U1    U2    G1   G2

3. 组网全过程（6 步走完）

阶段 1：邻居发现 —— 类比 5G 的"小区搜索"，但人人都在发

4G/5G 里是 gNB 周期广播 SSB/SIB，UE 被动扫。自组网里是每个节点都周期广播 HELLO 报文：

HELLO { 节点ID: "U1", 类型: "UAV", 位置: (x,y), 序列号: 37 }
  • U1 开机后广播 HELLO，同时收到 R1 的 HELLO → 知道自己有 1 个邻居 R1。
  • 通过双向握手确认"我发得出去、也收得到"（单向链路不算数）。

结果：每个节点本地形成一张邻居表（只存一跳邻居）：

邻居链路代价(ETX)最近HELLO有效期
R11.00.1s 前还剩 1.9s
这张表是分布式的——每个节点只存自己的局部信息，没有谁替你记全网。这正是和 4G/5G 最大的区别：没有"核心网"帮你记着全网。

阶段 2：接入选择与入网 —— 类比 attach，但可多跳

  • U1 根据代价选择接入邻居 R1。
  • 4G/5G 是"UE 只连基站"，自组网是"末端可连中继、也可连别的末端"，路径是多跳的。

阶段 3：拓扑建立 —— 从"局部邻居表"到"全网拓扑图"

每个节点只知道邻居，怎么让全网都知道拓扑长什么样？ 分两种思路：

  • 主动式（骨干/中继用）：每个节点把"我和谁连着、代价多少"（链路状态通告 LSA）洪泛给全网，最终每个节点都拼出全网拓扑图（OSPF 思路，RFC 2328；OLSR 用 MPR 减少洪泛冗余，RFC 3626）。
  • 反应式（末端接入用）：平时不维护全网，有数据才广播"找路请求(RREQ)"、目标回"应答(RREP)"（AODV，RFC 3561）。

同时，协调器 C 通过管控面收集全网快照，得到全局视图。

阶段 4：拓扑保存 —— 存哪、存什么

拓扑信息存在两个地方：

① 分布式（每个节点本地） —— 存"局部视图"（邻居表 + 路由表，见第 4 节）。

② 集中式（协调器 C） —— 存"全局快照"，用于全局优化和仲裁：

{
  "snapshotVersion": 123,
  "nodes": [{"nodeId":"U1","nodeType":"UAV","status":"up"}],
  "links": [
    {"linkId":"L17","linkType":"microwave","srcNodeId":"U1","dstNodeId":"R1",
     "status":"up","params":{"delayMs":12.5,"jitterMs":3.0,"bandwidthBps":8000000,
     "ber":0.0001,"packetLossRate":0.02},"tsUs":1798585182125680}
  ]
}
记忆点：节点存"我该往哪转发"（路由表），协调器存"全网长什么样"（快照）。

阶段 5：路由计算 —— 各算各的

  • 数据面：每个节点拿着全网拓扑图，本地跑 Dijkstra 算到各目的地的下一跳。
  • 管控面：协调器/资源 Agent 用 K 最短路 + 约束过滤(CSPF) 算候选路径，给全局调度用。

阶段 6：拓扑维护 —— 动态变化怎么办

机制做法类比 4G/5G
老化定时器HELLO 有 lifetime，超时没收到就删邻居类似 RRC 失步/RLF 检测
增量更新链路状态变了才洪泛变化部分类似"事件上报"而非全量刷新
失效重路由链路断了→局部修复/重算→换下一跳类似切换 handover / 重建

举例：R2 开机晚了，它开机广播 HELLO → G1、G2 发现新邻居 R2 → 更新路由表，流量切到 R2。这就是赛题"节点上线/下线"要模拟的过程。

4. 一个节点的"三张表"（你问的重点）

核心答案：路由表存的不是"邻居"，而是"到全网每个目的地的下一跳"。邻居只存在邻居表里。

表存什么类比
邻居表只有一跳直达的邻居 + 链路质量你只认识隔壁的人
拓扑表（链路状态库）全网地图（所有节点 + 所有链路）你手里有一整张地图
路由表到全网每个目的地的"下一跳"地图上算好的"去每个地方该走哪条街"

以 U1 为例，看三张表：

① 邻居表（一跳，只有 1 个）

邻居链路代价
R11.0

② 拓扑表（主动式协议洪泛学到的全网地图）

节点: C, B1, R1, R2, U1, U2, G1, G2
链路: C-B1, B1-R1, B1-R2, R1-U1, R1-U2, R2-G1, R2-G2

③ 路由表（全网 7 个目的地，但下一跳都是 R1）

目的地下一跳跳数
R1R11
U2R12
B1R12
R2R13
CR13
G1R14
G2R14

关键观察：

  • 邻居表只有 R1（一跳），但路由表有 7 个目的地——因为 U2、G1、C 虽然不挨着 U1，U1 依然要能"到达"它们。
  • 因为 U1 只有 R1 一个出口，所以所有目的地的"下一跳"都是 R1。"目的地"和"下一跳"是两个概念：目的地是最终收件人，下一跳是"这一站先交给谁"。

5. "目的地"是什么、怎么确定

目的地 = 某个节点的唯一标识（节点 ID / 地址），就像 IP 地址或电话号码。竞赛仿真里就是 nodeId（如 "C"、"G1"）。

目的地不是路由协议决定的，是业务/应用层决定的：

问题谁决定类比
我要发给谁？（目的地地址）业务/应用层打电话给谁，是"你"决定
知道了地址，怎么送过去？（下一跳）路由层电话网帮你接通线路

逐跳转发（hop-by-hop） 的过程，就像问路：

  • U1 的业务指令是"把侦察视频回传指挥所 C" → 数据包头上写目的地 C。
  • U1 查路由表：C → 下一跳 R1，交给 R1。
  • R1 查表：C → 下一跳 B1，交给 B1。
  • B1 查表：C → 下一跳 C（直达），送达。

每个节点只负责"下一跳给谁"，不负责全程。

6. 路由表里的"目的地条目"怎么学到

  • 主动式（OLSR，RFC 3626）：所有节点洪泛链路状态 → 每个节点拼出全网地图 → 路由表自然有了"到全网每个节点的条目"。
  • 反应式（AODV，RFC 3561）：平时不学，有数据要发到某目的地时，才临时广播找路、学到该目的地的路由。

类比 4G/5G：你的手机不需要"学全网路由"（核心网替你算），但自组网没有核心网，所以每个节点都得自己学、自己算——这就是"分布式"的含义。

7. 一句话总结

问题答案
组网过程邻居发现(HELLO) → 链路测量(ETX) → 拓扑洪泛(LSA) → 路由计算(Dijkstra) → 周期维护
拓扑怎么建立每个节点广播自己认识谁，拼出全网地图
拓扑怎么保存节点存"邻居表+路由表"，协调器存"全局快照"
拓扑怎么维护HELLO 老化定时器 + 链路状态增量更新 + 失效重路由
路由表存什么到全网每个目的地的下一跳，不是只存邻居
目的地是什么每个节点的唯一 ID（地址）
目的地怎么定业务层指定（我要发给 C），路由层只负责转发

和 4G/5G 的本质区别：蜂窝网拓扑是"静态的、核心网集中管的"；自组网拓扑是"动态的、每个节点自己算自己维护的"，协调器只是"全局参谋"，不是"唯一大脑"。
