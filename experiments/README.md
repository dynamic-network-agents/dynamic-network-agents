# 实验记录与问题清单（手工版）

本目录用于沉淀「实验记录 + 问题清单」，支撑初赛「实验验证(24) / 结果分析(16)」的叙事。**当前为手工版**——不依赖任何导入工具，编号、登记、关联都由人来做。

- 现阶段的完整方案与后续扩展计划（V1.5 统计脚本 → V2 静态导入 → V3 关联管理 → V4 运行时记录 → V5 知识沉淀）：[docs/experiments/现阶段方案.md](../docs/experiments/现阶段方案.md)
- 完整工具化设想（后续版本参考）：[docs/experiments/研发记录系统建设企划书.md](../docs/experiments/研发记录系统建设企划书.md)

## 目录约定

```
experiments/
├── README.md          # 本文件：工作流与约定
├── index.md           # 编号登记表（EXP + ISS 两个表，防冲突）
├── exp/               # 实验记录，一份实验一个文件
│   └── EXP-0001.md
└── iss/               # 问题记录，一个问题一个文件
    └── ISS-0001.md
```

模板参考：[docs/experiments/实验记录模板.md](../docs/experiments/实验记录模板.md) 与 [docs/experiments/问题清单模板.md](../docs/experiments/问题清单模板.md)。记录文件是模板的**实例**，从模板复制后填。

## 编号（手工，关键防冲突）

- 实验：`EXP-0001`、`EXP-0002`…… 问题：`ISS-0001`、`ISS-0002`……
- **新增前先到 `index.md` 占号**，再写文件，避免两人/两次之间撞号。
- 一个编号一旦用过就不复用；文件内容变了（输入文件哈希不同）就开**新 EXP 号**，不改旧记录。

## 标准工作流

1. **占号**：在 `index.md` 的对应表里加一行，写下下一个编号 + 标题 + 日期。
2. **写实验记录**：复制实验模板 → 填入场景来源（`suiteId` / `scenarioId` / `scriptId`）与真实统计 → 存到 `exp/EXP-xxxx.md`。
3. **写问题记录**：复制问题模板 → 填现象/预期/根因/修复/验证 → 存到 `iss/ISS-xxxx.md`。
4. **回填 index**：记录完成后把状态更新回 `index.md`。

## 关于「自动」字段

模板里标「自动生成 / 自动读取 / 自动计算」的字段，手工阶段一律：

- **能查到的就手填**（场景统计用脚本数、拓扑/业务 JSON 里的数）；
- **查不到或暂不需要的就留空或写「—」**，不编造、不填 0 冒充事实。

文件哈希如需要，可用 `shasum -a 256 <file>` 手算填入；不是必填。

## 关联（当前阶段先不建表）

按你的要求，**先不做独立关系表**。问题与实验的关联，暂时只用模板里的两个字段手动标：

- 问题模板 §2.8「关联实验」→ 写 `EXP-xxxx` + 关系类型（`discovered_in` / `verified_in` …）
- 实验模板 §9「关联问题」→ 写 `ISS-xxxx`

等实验/问题累积到几十个、写报告需要汇总反查时，再按企划书上 `relations/relations.json` 的关联管理。

## 硬约束

- **不虚构仿真运行数据**：`instanceId` / `t0TsUs` / 实测 QoS 等，未真正跑仿真就一律留空或写「V2 预留」，静态记录里不编造。
- **不记令牌/密钥**：`gateway.json` 的令牌、`eval/.env` 的密钥绝不写进任何记录。
- **事实与推断分开**：实测值 vs 静态需求 vs 分析结论分栏写，不混。
- 脚本事件 `time` 是相对 T0 的秒数，原样保存，不当绝对时间。
